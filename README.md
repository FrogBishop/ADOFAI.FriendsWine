# 朋友的酒 / FriendsWine

A Dance of Fire and Ice 的 UnityModManager 模组。按 **F8** 同时启用自带 BGM 和 130 BPM 拉伸，再按一次停止音乐并恢复画面。游戏启动时效果默认关闭。

1.0.2 增加视野裁剪和按需分配：即使整个拉伸周期的范围也不可能进入当前视野的对象，会跳过材质同步、顶点变形和副本处理。普通精灵和砖块网格保留原渲染器，游戏自己的透明度、出现、消失与渲染回调继续正常执行。

每拍 60/130 秒，分四段等长的线性动画：**原状 → 纵向拉伸 → 原状 → 横向拉伸 → 原状**。以每个图像自身的底边中心为原点，原点与坐标轴跟随物体旋转。文字按字处理，粒子按粒子处理。游戏暂停、切换场景和重开关卡不会重置时钟或停止 BGM。自带 BGM 与游戏音乐一起播放，播完自动循环。

## 使用

1. 安装 UnityModManager，并将 `FriendsWine` 文件夹放入游戏的 `Mods` 目录；也可通过 UMM 安装发行 ZIP。
2. 启动游戏，确认 UMM 中“朋友的酒”已加载。
3. 按 F8 开始或停止。打开 UMM（通常 Ctrl+F10），点击模组名称进入设置。
4. 修改四个倍数、音量或快捷键后，点击“保存并应用”。也可编辑模组目录里的 `settings.json`，然后点击“从配置文件重新载入”。

## 配置

| 配置项 | 默认值 | 含义 |
|---|---:|---|
| `VerticalX` | 0.75 | 纵向极值时的横向倍数 |
| `VerticalY` | 1.35 | 纵向极值时的纵向倍数 |
| `HorizontalX` | 1.35 | 横向极值时的横向倍数 |
| `HorizontalY` | 0.75 | 横向极值时的纵向倍数 |
| `Volume` | 0.5 | 独立 BGM 音量，0～1 |
| `ToggleKey` | `F8` | Unity KeyCode 名称，可写 `Ctrl+F8`、`Alt+F9` 等组合键 |

倍数必须是有限的正数；1 为原尺寸。修改配置不会重播正在播放的 BGM。保存配置会保留上一份 `settings.json.bak`。BGM 加载完成前不会单独启动画面效果。

## 构建与安装

需要 Windows、.NET SDK 10 和已安装 UnityModManager 的游戏。当前针对 Unity 6 版本的 ADOFAI 构建，在 r150 / Unity 6000.3.25f1 / UMM 0.33.3.0 验证。构建直接引用本机游戏 DLL，不从 NuGet 下载游戏依赖，也不将这些 DLL 打包或提交。

```powershell
./build.ps1 -GameDirectory 'C:\Program Files (x86)\Steam\steamapps\common\A Dance of Fire and Ice'
./install.ps1 -GameDirectory 'C:\Program Files (x86)\Steam\steamapps\common\A Dance of Fire and Ice'
```

也可设置 `ADOFAI_GAME_DIR`。不指定时使用 Steam 常见默认安装位置。安装前请退出游戏；安装脚本保留已有 `settings.json`。构建产物为 `dist/FriendsWine/` 和 `dist/FriendsWine-1.0.2.zip`，ZIP 名称自动跟随 Info.json 的版本。

根目录的原始 MP3 是源码资产。构建时复制成包内的 `Audio/bgm.mp3`，不需要在配置中填写绝对路径。`.gitignore` 已排除构建缓存、发行包、游戏 DLL、本机配置和日志；保留原始 MP3 与 `config.default.json`。

## 渲染实现与边界

- 每台相机先判断包含整个拉伸周期的保守包围范围，完全在视野外的对象只做轻量范围检查。只有通过裁剪后才创建变形资源；恢复阶段也只处理本次实际变形过的对象。移动物体或切换相机时重新判断，已经登记的对象进入视野后立即处理。
- 普通 SpriteRenderer 使用独立 Sprite 的位置顶点通道，保留原图集、UV、材质和原渲染器。MeshRenderer 使用临时变形网格。摄像机绘制完成后恢复原始 Sprite/网格，不修改共享源资产、游戏 Transform 或碰撞器。
- 原渲染器继续参与真实的 isVisible、OnWillRenderObject 和可见性通知，不再用 scrFloor 专用回调桥接冒充原生生命周期。实际顶点按当前相位变形，原生包围范围覆盖整个周期，避免边缘对象因压缩而频繁停掉游戏动画更新。
- Sliced/Tiled 精灵、SpriteMask、不可读网格及部分特殊网格仍使用按需创建的副本；SkinnedMeshRenderer、LineRenderer、TrailRenderer 使用绘制时烘焙。副本仅在绘制期间接入原层级。
- TextMeshPro 在原始排版网格生成后按字符修改顶点，覆盖多个字体材质、富文本和内嵌精灵；uGUI Image、RawImage 和旧 Text 使用网格效果。视野外的文字/UI 跳过重复重建，相机视锥按帧缓存。
- 粒子先显式烘焙世界坐标，再转换回源局部坐标，保留原有模拟空间与缩放语义。Billboard 使用每个四边形的独立底边和方向；单一可读 Mesh 粒子使用原网格恢复每颗粒子的局部方向。复杂多网格发射器的回退路径按 UV 方向下的连通网格块处理。
- IMGUI 控件背景、文字、直接 DrawTexture/DrawMesh 调用另有拦截；不会把已经合成的整幅画面再统一缩放。
- 活跃对象每 0.2 秒补充发现；新生成对象可能最多延迟约 0.2 秒加入效果。已存在对象的进出视野不等待这次扫描。停用时恢复原渲染器、重新生成文字和 UI，并移除绘制拦截。
- GPU 间接绘制、特殊自定义渲染管线或只在着色器中生成的图像可能无法分离为独立贴图。未适配的 Renderer 类型会记录在 UMM 日志中；不能保证任意第三方关卡/模组的特殊渲染路径全部覆盖。

## 验证与开发进度

`build.ps1` 默认执行无外部测试依赖的核心验证：四段节拍、四个独立倍数、线性中点、边界连续性、长时间循环和无累计漂移。

已完成实际游戏加载、12 帧旋转/翻转/嵌套原点检查、每字原点与比例检查、暂停下音频/动画继续、三次启停、BGM 循环、原生重开不重置时钟、配置往返和停用恢复。最新一轮集成断言全部通过，失效 Tween 警告为 0，截图已人工审查。没有遍历所有关卡和第三方模组。

1.0.2 在真实 1-1 关卡中对比了 8 类出现和 6 类消失动画，开始/中间/结束三个时点的像素、位置、缩放、旋转与透明度均匹配原游戏；连同透明度检查共 41 项通过。还验证了一万个对象的视野裁剪、仅拉伸后进入视野的边缘对象、原生渲染回调内的隐藏、多摄像机切换及偏心/翻转原点。

同机对照场景包含一万个对象和一个边缘对象：旧路径处理/分配 10001 份，新路径只处理/分配 9 份，跳过 9992 份。模组相机应用阶段的暖态中位耗时为约 196.1ms → 7.0ms。这是该场景中模组自身的处理时间，不是整个游戏的帧率，也不包含谱面本身的逻辑开销。

详细结果见 `VERIFICATION.md`；源码仓库中的 `PROGRESS.md` 是任务中断后的恢复入口。`verification/` 中的游戏内测试只在 `build.ps1 -IntegrationTest` 时编入，正式 DLL 不含测试入口。开发测试会启动自检并自动退出游戏，测试后应重新构建和安装正式版。
